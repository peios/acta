description: >-
  Create tasks, record requirements, divide work, and keep status aligned
  with results.
---

A task gives one piece of work a durable home. Its description states the
outcome; comments preserve the reasoning and evidence that lead to it.

## Before you start

Choose a workspace you can access. Creating work requires **Create tasks**;
changing an existing task requires **Edit tasks**. Search for the work before
creating a duplicate.

## Create and develop a task

1. Open **Tasks** or **Backlog** in the workspace.
2. Select **Create task**, enter a title naming the intended outcome, and
  create it.
3. Open the task and write its requirements and boundaries in the description.
4. Set its status and direct assignees. Add priority, type, size, or a target
  release when those choices are known.
5. Add subtasks for outcomes that need independent tracking.

The title and description save after a typing pause. Check the save indicator
before treating the record as saved. Comments use an explicit **Post** action.
If a conflict appears, compare your draft with the saved content before
retrying.

## Keep the record useful

Update the description when the agreed requirements change. Put progress,
architectural alternatives, decisions, and validation evidence in comments. A
comment that explains why a decision was made is more useful than a list of
commands run.

Assignments do not grant access or start an agent. Parent tasks display
descendant assignments as context, but each task keeps its own direct
assignments and status. Completing a parent does not complete its children, or
the reverse.

## Check the result

Reopen the task and check its saved description and properties. Copy its
reference or direct link when handing the work to someone else. References
survive workspace prefix changes; the underlying task UUID remains the same.

A completed task remains in active views unless their filters exclude it.
[Archiving Work](~acta/work/archiving) explains how to put it away without
deleting it.
